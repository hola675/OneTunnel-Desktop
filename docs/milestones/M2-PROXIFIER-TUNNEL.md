# M2-R — Xray + Proxifier selective tunnel

M2-R live rule certification **PASSED** on 2026-10-09 (M2-R.1).

## Objective

Certify an Xray loopback SOCKS tunnel, compatibility with the user-managed
corporate proxy path, and routing of one explicitly selected application
through that SOCKS endpoint. Windows-wide traffic capture is out of scope.

```text
Selected application
  → Proxifier rule: OneTunnel-Xray
  → Xray SOCKS5 127.0.0.1:10808 (certification default; must be free)
  → Xray VLESS + Reality (xtls-rprx-vision, Chrome fingerprint)
  → Proxifier rule: Corporate Proxy
  → 1VPN server:443
  → Internet
```

The loopback exclusion is DIRECT. The `xray.exe` rule must target Corporate
Proxy and must never target `OneTunnel-Xray`. Default remains DIRECT. Rules are
manual and external; see [Corporate Proxy](../CORPORATE-PROXY.md).

## Runtime behavior

Run `scripts/test-m2-proxifier-tunnel.ps1` in a normal PowerShell session.
The certification default is `-SocksPort 10808`; it fails with
`SOCKS_PORT_IN_USE` if occupied and never chooses a replacement. A different
port must be supplied explicitly and manually entered into Proxifier. Xray
binds only `127.0.0.1:<port>`.

The script validates runtime hashes (it does not execute Wintun or tun2socks),
detects Proxifier, selects a Free fixture server, creates and validates the
same Xray config as the certified Direct Gate, starts only its own Xray
process, and waits for the PID-owned loopback listener. It prints the fixed
SOCKS endpoint and waits while the user enables Verbose File Log and configures
rules manually. Then it sends HTTPS probes through Xray, from a selected
`curl.exe`, and from a distinct unselected PowerShell process. The selected
curl receives no proxy argument or proxy environment variable; `-q` disables
curlrc settings. Proxifier owns the process route.

TLS verification is STRICT first. The only fallback is curl exit 35 with the
exact Schannel revocation-offline marker (`CRYPT_E_REVOCATION_OFFLINE` or
`0x80092013`), after which `--ssl-revoke-best-effort` is used. Temporary
evidence contains egress hashes, not complete IP addresses. No Proxifier log
lines are printed, copied, or persisted. `-ProxifierLogPath` is read-only and
only the log interval generated by the probes is inspected. A missing log
means `PARTIAL PROXIFIER_EVIDENCE_MISSING`; a contradictory route fails the
corresponding gate.

The script cleans up only its Xray PID and temporary config and checks that
the SOCKS listener is gone. It never modifies Proxifier or Windows networking.

## Acceptance and status semantics

The live certification requires Xray HTTPS through SOCKS, a log entry showing
`xray.exe` routed through the named Corporate Proxy rule to the selected 1VPN
destination, a successful selected-app HTTPS request and `OneTunnel-Xray` rule
entry, an unselected process routed DIRECT (equivalent Default DIRECT
evidence), no Xray-to-OneTunnel loop, and successful cleanup. Egress IP hashes
are compared; if 1VPN egress varies, matching route evidence plus successful
tunnel traffic can certify the path without literal IP equality. Missing log
evidence returns `PARTIAL`; a wrong observed rule, loop, failed probe, or
cleanup returns `FAIL`.

The **LIVE CORPORATE TEST** uses the real user-managed proxy and rules above.
The script does not simulate Proxifier or modify its settings.

## M2-R.1 live certification

Result: **PASS**. The screenshot showed `xray.exe` assigned to
`OneTunnel-Xray-Outbound` with the corporate HTTPS proxy action, and
`curl.exe` assigned to `OneTunnel-Test-App` with the local SOCKS action. The
test then confirmed those rules in newly appended Verbose log records, plus
the unselected PowerShell process routed DIRECT. An earlier attempt reported
a false `PROXIFIER_LOOP` because the parser combined adjacent log lines and
mistook the corporate rule's `OneTunnel-Xray` name prefix for the selected
SOCKS rule. The parser now evaluates each connection record independently.

All three HTTPS probes passed. The selected curl request received no proxy
arguments or proxy environment variables. Selected and Xray egress hashes
matched; both differed from the unselected direct egress hash. The live
Xray-to-SOCKS loop check remained clear. Cleanup passed: only the test's Xray
PID and temporary config were removed, and the SOCKS listener was gone.
Proxifier remained running and unchanged. No raw log lines or complete egress
IP addresses were retained. Wintun and tun2socks were not used; Windows routes
and DNS were not modified.
